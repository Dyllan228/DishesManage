# 家庭私厨 · DishesManage

把「收藏了一堆菜谱却做不出来」变成「点几道菜，自动出备菜清单，照着做就行」。

纯本地的家庭菜谱与备菜管理工具：菜谱收集 → 多级分类 → 像点外卖一样点菜 → 自动合并出备菜清单。

## 快速开始

```bash
npm install
npm run dev        # http://localhost:5173
```

其他命令：

```bash
npm run build      # 类型检查 + 生产构建（含 PWA Service Worker）
npm run preview    # 预览构建产物
npm test           # 跑全部测试
npm run typecheck  # 只做类型检查
```

## 技术栈

| 层 | 选型 |
|---|---|
| 框架 | React 18 + TypeScript + Vite |
| 样式 | Tailwind CSS |
| 路由 | React Router v6 |
| 状态 | Zustand（只放跨页瞬时 UI 状态，业务数据不进全局 store） |
| 存储 | IndexedDB via Dexie |
| PWA | vite-plugin-pwa |
| 测试 | Vitest（含 fake-indexeddb 端到端测试） |

部署：纯静态，无后端。`npm run build` 产物直接扔 Vercel / Netlify 即可（自带 HTTPS，PWA 生效）。

两条硬约定（见 `docs/决策记录.md` D-002）：

1. **UI 层禁止直接 import `db`**，一律走 `repository`。V2 接云端同步时只换实现，UI 不动。
2. **领域逻辑必须是纯函数**，放 `src/domain/`，不碰数据库、不碰 React。

## 核心设计

**分类树（唯一归属）+ 标签（多对多）分离** —— 分类管「菜谱展示在哪」，标签管「跨分类筛选」，
避免「这道菜到底放哪个文件夹」的纠结。菜系是交叉属性，因此**不进分类树**，而是标签维度。

**粘贴解析是「辅助填表」，不是「自动入库」** —— 中文菜谱格式极度不统一，把「让用户确认」
做进流程，比追求解析准确率更可靠。

**清单合并宁可不合并，也不误合并** —— 番茄「2 个」与「200g」分成两行相邻展示并提示，
绝不凑成「202」。备菜清单算错比不算更糟。

**份量换算双场景分离** —— 菜谱里「1.5 个鸡蛋」保留精算值（做菜要按比例），
备菜清单里向上取整成「2 个」（买菜必须整数）。

**时间线是一条能说出口的规则，不是调度优化器** —— 「前置等待最长者先动，动手时间不重叠，
被动等待随便叠」。用户看得懂才会照着做；算得更优但说不清楚，遇到一次"为什么让我先做这个"
就不会再用了。

## 怎么用

1. **收菜谱**：菜谱页「＋」手动录入，或「粘贴导入」把一整段中文菜谱贴进来，
   解析出草稿后逐字段确认。
2. **点菜**：在菜谱里挑几道加进今日菜单，用加减号调份量（1.5×、2×）。
3. **备菜**：生成合并去重的清单，同名食材自动累加，不可分割单位向上取整。
4. **做菜**：菜单里点「开始做菜」进制作模式——大字步骤、屏幕常亮、点一下启动计时器，
   切到别的页面计时器照样在跑。
5. **安排多道菜**：菜单页「🕒 时间线」告诉你什么时候该动手、现在同时在做什么、
   哪段时间可以走开。
6. **回看**：做完打星 + 记一句感受，历史页按日期翻，想复刻某一顿点「照着再来一次」。

## 数据说明

所有数据存在浏览器本地 IndexedDB，不上传任何服务器。清除浏览器数据会连数据一起清掉，
**重要数据请定期导出备份**（设置 → 备份与恢复，超过 30 天没备份会提醒）。

导出的两种格式用途不同：**JSON 是完整备份**，能在应用里原样恢复（换设备、找回误删都用它）；
**Excel 是给人看的**，多 Sheet 摊平，方便打印或拿去别处整理，不能导回。

删掉的菜谱进回收站保留 30 天，期间可随时恢复。
